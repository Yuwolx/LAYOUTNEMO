## 무슨 일이 있었나

LAYOUTNEMO의 캔버스는 처음부터 끝까지 **마우스**를 전제로 만들어졌다. 드래그로 옮기고, 모서리를 잡고, modifier 키(Shift·Alt·Ctrl·Space)로 연결·복사·선택·팬을 구분했다. 그런데 태블릿에서 열어 보면 아무것도 제대로 안 됐다. 손가락으로 블럭을 끌면 **페이지가 스크롤**됐고, 두 손가락을 대면 브라우저가 **줌**을 가져갔고, ⋮ 메뉴는 hover가 없으니 **영영 안 보였다.**

"태블릿에서도 쓰고 싶다"가 이번 목표였다. 다만 **마우스 경험을 하나도 망가뜨리지 않으면서**.

---

## 전제부터: 마우스와 터치를 하나로

가장 먼저 정한 건 "터치용 코드를 따로 만들지 않는다"였다. `mousedown`/`mousemove` 옆에 `touchstart`/`touchmove`를 나란히 붙이면, 같은 로직이 두 벌이 되고 둘이 조금씩 어긋나면서 버그가 난다.

그래서 **Pointer Events**로 갈아탔다. `pointerdown`/`pointermove`/`pointerup` 하나가 마우스·터치·펜을 전부 대신한다. `PointerEvent`는 `MouseEvent`를 상속하니 기존에 읽던 `clientX/Y`, `shiftKey`, `altKey`가 그대로 살아 있고, 거기에 `pointerType`("mouse" / "touch" / "pen")과 `pointerId`가 더해진다.

- `pointerType`으로 **"지금 터치인가"**를 분기하고,
- `pointerId`로 **"이 손가락"**만 추적한다.

마우스 경로는 이벤트 이름만 바뀌었을 뿐 로직이 그대로라, 회귀가 거의 없었다.

### 브라우저에게서 제스처 뺏어오기

터치의 첫 벽은 브라우저였다. 손가락으로 캔버스를 끌면 브라우저는 그걸 **스크롤**로, 두 손가락은 **핀치 줌**으로 해석해 버린다. 정답은 CSS 한 줄, `touch-action: none`. 캔버스와 블럭 카드에 걸어 "이 영역의 터치 제스처는 내가 직접 처리한다"고 선언했다. iOS에서 롱프레스 시 뜨는 텍스트 선택 콜아웃(`-webkit-touch-callout`)과 텍스트 선택(`user-select`)도 같이 껐다 — 드래그를 방해하기 때문이다.

### 두 번째 손가락은 무시한다

터치는 마우스와 달리 **동시에 여러 개**가 들어온다. 한 손가락으로 블럭을 끄는 도중에 다른 손가락이 화면에 닿으면 상태가 엉킨다. 그래서 `activePointerId` 한 칸을 두고, **처음 인터랙션을 시작한 포인터**만 붙잡았다.

```
if (activePointerIdRef.current !== null) return  // 이미 다른 포인터가 잡고 있음
...
activePointerIdRef.current = e.pointerId          // 이 포인터로 고정
```

이후 `pointermove`/`pointerup`는 `e.pointerId === activePointerIdRef.current`일 때만 반응한다. 두 번째 손가락은 조용히 무시된다. 핀치 줌은 아직 없지만(다음 단계), 적어도 **두 손가락이 캔버스를 깨뜨리진 않는다.**

---

## modifier 키가 없는 세계

여기서부터가 진짜 문제였다. 마우스 인터랙션의 절반은 **키보드 modifier**로 구분됐는데, 태블릿엔 키보드가 없다.

| 마우스 | 터치 대체 |
|---|---|
| 그냥 드래그 → 이동 | 그대로 (한 손가락 드래그) |
| 빈 곳 드래그 → (없음) | **한 손가락 팬** |
| Space + 드래그 → 팬 | (팬이 기본이 됨) |
| Alt + 클릭 → 복사 | **⋮ 메뉴 → 복사** |
| Shift + 드롭 → 연결 | **⋮ 메뉴 → 연결** |
| Ctrl + 드래그/클릭 → 선택 | **선택 모드 토글 버튼** |
| hover → ⋮ 노출 | 터치 기기에선 **항상 노출** |

핵심은 **사라진 modifier를 화면 위 어포던스로 옮기는 것**이었다.

### 팬: 빈 곳은 그냥 끌면 된다

마우스에선 팬이 `Space + 드래그`였지만, 터치에선 **빈 캔버스를 한 손가락으로 끌면 팬**이 자연스럽다(지도 앱이 다 그렇다). 블럭 위에서 시작하면 블럭 이동, 빈 곳에서 시작하면 팬 — `pointerType === "touch"`일 때만 이 규칙을 켰다.

### 연결·복사: 손가락엔 Shift가 없다

연결(관계선)은 원래 `Shift + 드롭`이라는 **드래그 제스처**였다. 터치로 옮기려다, 와이어를 끌어다 잇는 방식은 정확도가 필요해 접었다(기획 단계에서 정한 방향). 대신 **메뉴 기반**으로 갔다.

- 블럭 ⋮ 메뉴에서 **'연결'** → 연결 모드 진입, 소스 블럭에 보라 링이 뜨고 하단에 "연결할 블럭을 탭하세요" 배너
- **대상 블럭을 탭**하면 두 블럭이 이어지고 모드 종료
- 소스를 다시 탭하거나 빈 곳을 탭하면 취소

복사도 `Alt + 클릭`에서 **⋮ 메뉴 → 복사**로 옮겼다. 덤으로 이 둘은 마우스 사용자도 메뉴로 쓸 수 있게 됐다.

### 선택: Ctrl 대신 모드 버튼

멀티 선택은 [바로 전 작업](2026-07-02-multi-select-and-pin.md)에서 `Ctrl`에 걸어뒀는데, 터치엔 Ctrl이 없다. 그래서 화면 좌하단에 **'선택 모드'** 토글 버튼을 뒀다(hover 없는 기기에서만 노출). 켜면 탭이 선택 토글, 빈 곳 드래그가 마퀴 선택이 되고, 끄면 다시 이동 모드로 돌아온다. 마우스의 `Ctrl` 분기와 **완전히 같은 코드**를 타되, 조건에 `(pointerType === "touch" && touchSelectMode)`만 더했다.

## 검토에서 걸린 것들

구현 뒤 스스로 세 번 훑었는데, 눈에 안 띄던 것들이 나왔다.

- **링크와 ⋮ 버튼이 드래그를 시작시켰다.** 외부 링크 `<a>`와 ⋮ 버튼엔 원래 `onMouseDown`으로 전파를 막아뒀는데, 드래그가 Pointer로 바뀌면서 그 방어가 무력해졌다. 탭하면 링크로 가는 대신 카드가 끌려왔다. `onPointerDown`으로 바꿔 막았다. **이벤트 종류를 갈아탈 땐 "막아두던 곳"도 같이 갈아타야 한다.**
- **팬을 하면 선택이 풀렸다.** 처음엔 터치 팬 시작 시 선택을 비웠는데, "선택해 두고 팬으로 훑어보다 잃는" 게 더 답답했다. 팬 중엔 선택을 **유지**하도록 고쳤다.
- **연결 중인 소스가 안 보였다.** 어느 블럭에서 연결을 시작했는지 표시가 없어, 소스에 선택과 같은 보라 링을 띄웠다.

## 정리

이번 작업의 8할은 **"마우스에만 있던 것을 터치에서 어떻게 대신하나"**였다. 코드보다 **매핑 표**를 그리는 데 시간이 더 걸렸다.

배운 것:

- 입력 장치를 늘릴 땐 **Pointer Events로 경로를 하나로 합치는 게** 두 벌 코드보다 안전하다. 마우스 회귀가 거의 없었던 이유다.
- 터치는 **브라우저와 제스처를 두고 다툰다.** `touch-action: none`으로 먼저 소유권을 가져와야 시작할 수 있다.
- **modifier 키는 화면 위 어포던스로 번역**해야 한다 — 팬은 기본 제스처로, 연결·복사는 메뉴로, 선택은 모드 버튼으로.
- 이벤트 모델을 바꾸면 **"전파를 막던 자리"가 조용히 뚫린다.** 링크·버튼처럼 드래그를 막던 곳을 반드시 같이 점검한다.

아직 남은 건 **핀치 줌**(두 손가락 확대·축소)과 **휴대폰용 반응형 레이아웃**이다. 이번엔 태블릿까지를 목표로 잡고 그 둘은 다음으로 미뤄뒀다. 로컬에선 컴파일·부팅까지만 확인 가능하니, 실제 감각은 기기에서 만져보며 다듬어야 한다. 캔버스 도구는 결국 **손에 익는 제스처를 하나씩 늘려가는** 일이다 — 이번엔 그 '손'이 진짜 손가락이었다.
