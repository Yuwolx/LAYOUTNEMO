## 뭘 만들었나

### 1. Google OAuth 로그인

버튼 하나. Google 로고 + "로그인" 세 글자.

Supabase Auth를 붙였다. `@supabase/ssr` 패키지로 서버/클라이언트 쿠키를 분리해서 관리한다. 로그인 후에는 이름이 드롭다운으로 표시된다. 로그인 없이도 기존처럼 로컬 모드로 사용할 수 있다.

생각보다 삽질이 있었다. Google 제공자를 Supabase 대시보드에서 직접 활성화하지 않으면 `Unsupported provider: provider is not enabled` 에러가 나는데, 에러 메시지만 보면 코드 문제처럼 보인다. 설정이 누락된 거였다.

### 2. 멀티 디바이스 동기화

로그인하면 캔버스/결/블럭 전체가 Supabase PostgreSQL에 저장된다.

충돌 해결 전략은 단순하게 잡았다. **서버 우선**. 로그아웃 시점에 `lastSyncedAt` 타임스탬프를 로컬에 저장해두고, 재로그인 시 그 이후로 서버와 로컬이 둘 다 바뀐 캔버스가 있으면 서버 것을 쓴다.

복잡한 3-way merge 같은 건 안 했다. 지금 단계에서는 "마지막으로 서버에 저장된 게 진실"이면 충분하다.

```typescript
// 충돌 감지 로직 요약
const lastSyncedAt = parseInt(localStorage.getItem("layout_last_synced_at") ?? "0")

// 서버와 로컬이 lastSyncedAt 이후 둘 다 변경됐으면 → 서버 우선
// 로컬만 변경됐으면 → 로컬 데이터를 서버에 업로드
// 서버만 변경됐으면 → 서버 데이터 사용
```

### 3. Supabase 스키마

테이블 5개로 구성했다.

| 테이블 | 역할 |
|--------|------|
| `user_profiles` | 이메일, 플랜, 가입일 |
| `canvases` | 캔버스 메타데이터 |
| `zones` | 결(Facet) |
| `blocks` | 블럭 전체 (is_deleted 포함) |
| `events` | 유저 행동 이벤트 |

RLS(Row Level Security)로 사용자 간 데이터 격리. 미들웨어에서 직접 RLS를 체크하면 재귀 문제가 생기기 때문에 `security definer` 함수를 따로 만들어서 우회했다.

### 4. 이벤트 트래킹 + 관리자 대시보드

외부 분석 도구 없이 자체 `events` 테이블에 쌓는다. fire-and-forget 패턴으로 추적 실패가 메인 플로우를 막지 않도록 했다.

```typescript
export function captureEvent(supabase, userId, name: EventName, payload?) {
  supabase.from("events").insert({ user_id: userId, name, payload: payload ?? {} }).then()
  // 반환값 무시 — 실패해도 사용자 경험에 영향 없음
}
```

현재 추적하는 이벤트: `session_start`, `block_created`, `block_deleted`, `ai_create_used`, `ai_tidy_used`.

`/admin` 경로에 대시보드를 만들었다. Google OAuth와 완전히 분리된 별도 ID/PW 로그인. httpOnly 쿠키 8시간 유효. 대시보드에는 DAU 30일 추이, 블럭 생성 추이, AI 사용량, 유저 목록이 있다.

왜 분리했냐면: 서비스 운영 계정이 Google 계정 하나에 묶이는 게 싫었다. 관리자 접근 권한은 환경변수(`ADMIN_ID`, `ADMIN_PASSWORD`)로만 관리한다. 당연히 `NEXT_PUBLIC_` 접두사 없이.

## 블럭 카드 UI 개편

이건 사실 v2의 인프라 작업과 별개로 진행된 UX 결정이다.

기존에는 블럭에 **설명**과 **상세 메모** 두 개의 텍스트 필드가 있었다. 설명은 카드 외부에서 보이고, 상세 메모는 클릭해서 열어야만 보였다.

문제는 이 둘이 기능적으로 겹쳤다. "설명 칸에 뭘 써야 하고, 상세 메모 칸에는 뭘 써야 하지?"

그냥 합쳤다. 설명 삭제, 상세 메모를 **메모**로 이름 바꾸고, 카드 외부에서도 바로 보이게 했다.

```tsx
// 이전: description을 카드에 표시
const displayDescription = translateSeedBlockField(block, "description", language) ?? block.description

// 이후: detailedNotes(메모)를 표시, 구 데이터 폴백
const displayNotes = translateSeedBlockField(block, "detailedNotes", language)
  ?? block.detailedNotes
  ?? block.description  // 기존 데이터 하위 호환
```

줄바꿈도 제대로 지원한다(`whitespace-pre-wrap`). 최대 5줄. AI로 블럭을 만들면 AI가 생성한 1줄 요약이 메모에 자동으로 들어간다.

글씨 크기도 조금씩 키웠다. 제목 13→14px, 메모 11→12px, 날짜/링크 10→11px. 작은 차이지만 읽기 훨씬 편해졌다.

## AI 개선 — 메모 내용도 분석에 반영

`/api/ai/tidy-comprehensive`에서 블럭 유사도를 계산할 때 기존에는 `description` 필드만 봤다.

```typescript
// 이전
const text1 = `${block1.title} ${block1.description || ""}`.toLowerCase()

// 이후
const text1 = `${block1.title} ${block1.detailedNotes || block1.description || ""}`.toLowerCase()
```

메모에 실질적인 업무 내용을 더 많이 쓰게 됐으니, 유사도 계산도 메모 내용을 먼저 보는 게 맞다.

새 블럭 배치 알고리즘도 손봤다. 기존에 새 블럭 크기를 96px로 가정하고 겹침을 감지했는데, 실제 블럭은 메모가 있으면 130px 이상으로 커진다. `BLOCK_HEIGHT = 130`으로 조정하니 배치 직후 겹침이 줄었다.

## 남은 것들

솔직하게.

### rate limit 없음

AI 엔드포인트 두 개에 여전히 rate limit이 없다. 로그인 여부 체크 정도는 서버에서 할 수 있지만, 로그인 없이도 AI를 쓸 수 있는 구조라 완전히 막기가 애매하다. Vercel Edge Middleware로 IP 기반 제한이라도 걸어야 한다.

### 유료 플랜 미구현

`user_profiles.plan` 컬럼은 있다. 코드에도 `plan === "pro"` 체크가 관리자 대시보드에 들어있다. 그런데 실제로 유료 전환 플로우(결제, 플랜 업그레이드)는 아직 없다.

멀티 캔버스를 무료로 얼마나 열어줄지, 유료는 어디까지 허용할지 — 이 정책 결정이 선행되어야 코드를 짤 수 있다. 일부러 남겨뒀다.

### God Component 두 개

`app/page.tsx`가 800줄에 가깝다. 캔버스 상태 관리, 블럭 CRUD, Supabase 동기화, 키보드 단축키, Undo/Redo가 한 파일에 있다. 당장 동작은 문제없지만, 건드릴 때마다 파일 전체를 훑어야 한다.

분리할 타이밍이 오겠지. 아직은 아니다.

## 마치며

v1이 "혼자 쓰는 캔버스"였다면 v2는 "어디서든 이어 쓰는 캔버스"다.

인프라 작업이 많아서 겉으로 보이는 변화는 로그인 버튼 하나뿐이지만, 밑에서 바뀐 게 많다. 데이터가 서버에 쌓이기 시작했고, 누가 어떻게 쓰는지 볼 수 있게 됐다.

다음은 유료 플랜 설계와 rate limit. 둘 다 기능보다 정책을 먼저 결정해야 하는 일이다.
