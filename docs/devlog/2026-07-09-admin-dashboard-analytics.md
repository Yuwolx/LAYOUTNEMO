# 숫자 4개짜리 대시보드를 분석 도구로 — 코호트, 퍼널, 그리고 KST 함정

## 무슨 일이 있었나

관리자 대시보드는 v2 때 만든 뼈대 그대로였다 — 통계 카드 4개(총 유저 / 오늘 가입 / 총 블록 / 이번달 AI), 차트 3개, 유저 50명 목록. "서비스가 살아 있나" 정도는 보이지만 "어디가 아픈가"는 안 보였다. 요청은 명확했다: **운영자·마케터·분석가가 인사이트를 얻을 수 있게, 최대한 많은 정보를.** 단, 많아져도 가시성을 잃지 말 것.

## 이벤트 5종으로 어디까지 가나

수집하는 이벤트는 딱 다섯 개다 — `session_start`, `block_created`, `block_deleted`, `ai_create_used`, `ai_tidy_used`. 새 수집을 추가하면 데이터가 쌓일 때까지 몇 주를 기다려야 하니, **이미 쌓인 것만으로 뽑을 수 있는 최대치**를 먼저 갔다. 의외로 표준 분석 지표 대부분이 나온다:

- **DAU/WAU/MAU + Stickiness**(평균 DAU÷MAU) — `session_start` 하나로
- **리텐션 코호트** — 주간 가입자 × 경과 주차별 재방문율 그리드. 가입일(`user_profiles.created_at`) × 세션 주차 매칭
- **활성화 퍼널** — 가입 → 7일 내 첫 블록 → 7일 내 AI 사용. 유저별 최초 이벤트 시각만 있으면 됨
- **신규 vs 기존 DAU 분해** — 오늘 활성 유저 중 가입 7일 이내 비율. 성장이 유입인지 재방문인지 갈라 보임
- **이탈 위험/복귀 세그먼트** — 30일 내 활동했으나 최근 14일 무활동 / 3주 잠잠하다 재방문

쿼리 폭발이 걱정이었는데, 결론은 **9주치 이벤트를 한 번에 가져와 단일 순회로 전부 집계**하는 것이었다. 코호트 8주 + 여유 1주가 필요한 최대 범위라서 그 창 하나로 DAU 시리즈·히트맵·코호트·퍼널·세그먼트·유저별 마지막 활동까지 다 나온다. 원시 이벤트를 클라이언트로 내려보내던 기존 방식도 서버 집계로 바꿔 페이로드가 오히려 줄었다.

## 함정: 아침 9시 전의 하루는 어제였다

기존 코드의 날짜 버킷은 `created_at.split("T")[0]` — **UTC 기준**이다. 한국 사용자가 아침 8시에 접속하면 UTC로는 전날 23시라서, DAU가 전날로 잡힌다. 매일 오전 9시 이전의 활동 전부가 하루씩 밀려 있던 셈이다.

```
UTC 버킷: 07-09 08:30 KST 접속 → "07-08" 로 집계 (밀림)
KST 버킷: ts + 9h 후 날짜 추출 → "07-09" (정확)
```

일별 시리즈·히트맵·코호트 주차·"오늘 가입" 경계까지 전부 KST 기준으로 교정하고, 헬퍼는 `lib/admin/kst.ts`로 빼서 두 API 라우트가 공유한다. 통계가 하루 밀리는 건 티가 잘 안 나는 종류의 버그라, 이번에 대시보드를 갈아엎지 않았으면 계속 몰랐을 것이다.

## 행을 누르면 그 유저가 보인다

집계 숫자는 평균의 함정이 있다. 그래서 유저 목록의 행을 누르면 **그 유저 하나의 드릴다운 모달**이 열리게 했다 — 블록 구성(활성/완료/삭제), 시급도 분포, 캔버스 목록(블록 수·마지막 수정), 30일 활동(접속·블록 생성·AI 3선). 파워 유저가 어떻게 쓰는지, 이탈 직전 유저가 마지막에 뭘 했는지를 개별로 확인할 수 있다.

## 정보가 늘면 UI 가 무너진다 — 탭과 해석 힌트

카드 4개가 타일 12개 + 차트 9개 + 그리드 2개가 되면 한 페이지로는 스크롤 지옥이다. 두 가지로 정리했다:

- **관심사 3탭** — `개요`(현황 스냅샷) / `성장 · 진단`(코호트·퍼널·건강 지표) / `유저`(참여 분포·목록). 매일 보는 것과 주 1회 보는 것을 분리.
- **타일마다 해석 힌트** — 숫자 밑에 "평균 DAU ÷ MAU — 습관성", "30일 삭제 ÷ 생성 — 높으면 정리 부담 신호" 같은 한 줄. 지표 이름을 아는 사람만 읽을 수 있는 대시보드는 반쪽이다.

## 차트 색도 감이 아니라 계산으로

다크 모드 때 배운 걸 그대로 적용했다 — 색은 눈이 아니라 검증기로. 색약(CVD) 시뮬레이션 색차와 표면 대비를 라이트/다크 양쪽에서 돌렸더니, 기존에 쓰던 앰버 `#f59e0b`가 **다크 표면에서 명도 밴드 탈락**(너무 밝아 형광처럼 뜸). 한 단계 어두운 `#d97706`으로 교체해 인디고/앰버/레드 3색을 확정했다. 시급도 분포 차트만은 예외로 — 그건 제품 의미색이므로 `urgency.ts` 단일 소스의 파스텔 4색을 그대로 쓴다. 차트 팔레트와 제품 의미색을 섞지 않는 것.

## 정리

- **새 수집보다 기존 데이터의 최대치가 먼저다.** 이벤트 5종으로 코호트·퍼널·세그먼트까지 나온다. 수집 추가는 그다음.
- **날짜 버킷은 반드시 사용자 시간대로.** UTC `split("T")[0]`은 한국 서비스에서 오전 9시 이전을 전날로 밀어 넣는다. 조용히 틀리는 버그라 더 위험하다.
- **집계는 서버에서, 조회는 한 창으로.** 필요한 최대 기간(9주)을 한 번 가져와 단일 순회로 전 지표를 뽑으면 쿼리 수·페이로드 둘 다 준다.
- **지표가 늘면 탭과 해석 힌트로 시야를 지킨다.** 숫자 밑 한 줄 설명이 대시보드를 "아는 사람 전용"에서 꺼내 준다.
- **평균 뒤에 개인을 둔다.** 집계 차트 옆에 유저 드릴다운이 있어야 "왜"까지 간다.

한계도 적어 둔다: 코호트·퍼널은 `session_start` 이벤트 기반이라 **이벤트 수집이 시작된 시점 이전 주차는 실제보다 낮게** 보인다. 몇 주 지나면 자연히 채워진다. 롤백 지점은 `release/pre-admin-dashboard`.
