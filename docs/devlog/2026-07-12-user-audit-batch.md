## 감사 방식: 세 갈래로 나눠 훑기

오전에 캔버스 제한 + PWA 가로 터치 대응을 배포한 직후라, 바뀐 표면을 기준으로 세 방향을 병렬로 조사했다.

1. **캔버스 관리 엣지케이스** — 마지막 캔버스 삭제, 한도와 얽히는 모든 생성/삭제/초기화 경로
2. **영어 모드 한국어 누수** — "전수 제거"를 했다고 믿는 상태에서 다시 전수 검사
3. **viewport-fit=cover 여파** — 화면 가장자리에 붙은 모든 fixed/absolute UI

결과: 잘 만들어진 부분이 더 많았다(마지막 캔버스 삭제 이중 가드, 초기화 항상 1개 보장, 토스트 전량 한영 분기…). 하지만 7건이 남아 있었다.

## 잡힌 것들

**"전수 제거" 뒤에도 남는 누수는 앱 바깥 표면에 있다.** 영어 누수 4곳의 공통점: 전부 i18n Provider 가 닿지 않는 곳이었다. 크래시 화면(error boundary 는 Provider 트리 밖), PWA 매니페스트(정적 라우트), AI 실패 시 클라이언트 폴백(mock 함수), aria-label. 컴포넌트 트리 안쪽을 아무리 청소해도 트리 밖 표면은 따로 세어야 한다. 크래시 화면은 저장된 언어 설정 → 브라우저 언어 순으로 직접 판별하게 했고, 매니페스트는 layout 메타데이터와 같은 accept-language 분기를 달았다.

**최악의 카피는 "돈 낸 사람에게 유료 플랜 준비 중".** 캔버스 잠금 판정이 프로필(plan) 로딩 완료를 기다리지 않아서, pro 유저도 로딩 창 동안 — 프로필 fetch 가 실패하면 영구히 — "추가 캔버스는 준비 중인 유료 플랜에서 열려요"를 보게 돼 있었다. 지금은 pro 유저가 0명이라 안 터졌지만, 유료화 출시 후였다면 환불 사유다. 플랜 로딩 전엔 잠금 문구 대신 중립 상태를 보여주도록 3-상태로 바꿨다. 생성 가드 자체는 유지라 로딩 틈의 우회도 없다.

**한도를 걸면 비가역 경계가 새로 생긴다.** 제한 이전부터 캔버스를 여러 개 갖고 있던 무료 유저는 그대로 쓸 수 있게 뒀는데(grandfathering), 이 유저가 하나를 지우는 순간 그 슬롯은 무료 한도 때문에 영영 회수된다. 삭제 확인창은 "블럭이 사라져요"만 경고하고 있었다. "삭제 후 새 캔버스를 다시 만들 수 없어요" 한 줄을 추가했다 — 기능을 잠글 때는 잠금이 만들어내는 **새로운 비가역 지점**까지 카피에 반영해야 한다.

**cover 여파는 예상보다 작았다.** 세 번째 조사는 대부분 "문제 없음"으로 끝났다(헤더 상단은 default 상태 바 기준으론 패딩 불필요가 맞고, Radix 팝오버는 자체 충돌 회피). 유일한 실수정: create-block-dialog 만 max-h 가 없어서 짧은 폰 가로에서 위아래로 넘칠 수 있었다 — 86vh + 스크롤로 캡.

## 정리

- **i18n 전수 검사는 Provider 트리 밖까지.** error boundary, manifest, 클라이언트 폴백, aria-label — "컴포넌트가 아닌 표면"이 마지막까지 남는다.
- **플랜 게이트는 로딩 상태가 3-상태다.** free / pro / **아직 모름**. "아직 모름"을 free 로 취급하면 카피가 유료 유저를 모욕한다.
- **제한 기능은 비가역 경계를 새로 만든다.** 그 경계를 넘는 액션(여기선 삭제)의 확인창에 경고를 심을 것.
- 감사 자체가 싸다. 걸린 7건 전부 코드 반나절 분량이었고, 유저가 먼저 걸었으면 각각이 피드백 응대 + 신뢰 비용이었다.

롤백 지점은 `release/pre-ux-audit`.
