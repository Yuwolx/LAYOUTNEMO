# 동기화 알림, 패널에서 아이콘으로 — 성공은 조용히, 예외만 크게

## 문제: "동기화됐어요"가 패널로 뜬다

사용자(나)의 불만은 단순했다: 다른 기기로 접속하면 동기화됐다는 패널이 뜨는데, 더 세련된 방식은 없나. 코드를 보니 정체는 top-center sonner 토스트 — 제목 + 설명 + 닫기 버튼에 8초 지속이라, 폰에서는 화면 상단을 차지하는 패널처럼 보인다.

그런데 이 토스트는 원래 "항상" 뜨라고 만든 게 아니었다. 로그인 병합은 클라우드 우선이라, 클라우드에 못 올라간 로컬 편집이 있으면 덮어쓰기 전에 백업하고 그 사실을 알리는 예외용 알림이었다. 예외용 알림이 왜 매번 뜨나?

## 원인: 2초 debounce 와 last_synced_at 의 틈

클라우드 저장은 2초 debounce 로 모아서 나간다. 폰에서 블럭 하나 옮기고 바로 앱을 닫으면(휴대폰에서는 이게 기본 사용 패턴이다) debounce 가 못 돌고, 저장 성공 시에만 기록되는 `last_synced_at` 이 낡은 채 남는다. 다음 접속에서 부트 로직은 `canvas.updatedAt > last_synced_at` 을 보고 "오프라인 편집이 있었다"고 판단 — 백업 + 8초 토스트. 즉 알림 자체는 정직하게 일했고, 알림을 트리거하는 감지가 과민했던 것.

## 다른 서비스들은 어떻게 하나

방향을 정하기 전에 업계 패턴을 훑었다. Google Docs 는 툴바 구석의 회색 글씨 한 줄("모든 변경사항이 저장됨"), Notion 은 성공 시 아무것도 안 보여주고 오프라인일 때만 배지, Apple 메모는 동기화 중 스피너만 잠깐, Obsidian Sync 는 상태바의 작은 아이콘. 공통 원칙:

> **동기화 성공은 당연한 것이라 알림감이 아니다. 궁금할 때 확인할 수 있는 조용한 상태 표시면 충분하고, 토스트는 실패·충돌·백업 같은 반드시 알아야 할 예외에만.**

## 수정 1 — 헤더의 조용한 구름

로그인 상태의 헤더 오른쪽에 작은 구름 아이콘 하나. 동기화 중엔 은은한 펄스, 완료되면 저채도 회색으로 정지, 연결 문제면 앰버 CloudOff(공지=앰버 관례 재사용, 시급도 4색과 안 겹침). 탭하면 "동기화됨 · 방금 전"을 2초짜리 미니 토스트로 보여준다. 상태 배선은 편집 → syncing, 저장 성공 → synced, 실패 → error 의 단순한 3상태.

## 수정 2 — 탭 이탈 시 클라우드도 flush

근본 원인 쪽. 로컬 저장은 이미 pagehide/visibilitychange 에서 즉시 flush 하고 있었는데(7/15 감사), 클라우드는 백로그에 걸어두고 안 하고 있었다. 이번에 붙였다: 탭을 벗어날 때 미반영 변경이 있으면 debounce 타이머를 걷고 즉시 저장. 편집이 제때 클라우드에 도착하니 `last_synced_at` 이 갱신되고, 다음 부트의 "오프라인 편집" 오판이 구조적으로 사라진다. 백업 토스트는 진짜 예외(하드 킬로 저장이 정말 죽은 경우)에만 남고, 문구도 실제 상황에 맞게 고쳤다 — 기존 문구는 "로그아웃 중 바꾼 내용"이라고 했는데 로그인한 채로도 뜨는 상황이었으니 거짓말이었던 셈.

## 리뷰가 잡은 것: 침묵 유실 두 건

머지 전 리뷰(서브에이전트)가 Critical 은 없다면서 Important 두 건을 짚었는데, 둘 다 "이 PR 이 잡으려던 버그의 침묵 버전"이었다.

**하나.** 저장 성공 핸들러가 `last_synced_at` 을 무조건 찍고 있었다. 저장 A 가 나는 동안 새 편집이 생기고, A 가 편집 이후에 성공하면 시각은 편집보다 미래 — 후속 저장 B 가 죽으면 다음 부트가 그 편집을 "이미 동기화됨"으로 오판해 **백업도 토스트도 없이** 덮어쓴다. 원래 있던 코드지만, 시끄러운 유실(백업 있음)만 고치고 조용한 유실(백업 없음)을 두면 반쪽이다. 수정은 한 줄: 시각 기록을 dirty 가드 안으로. 시각이 낡은 쪽의 비용은 불필요한 백업 하나뿐이고, 시각이 앞서는 쪽의 비용은 데이터다.

**둘.** `flushCloudSave` 에 in-flight 가드가 없어서, 이번에 추가한 pagehide flush 가 진행 중인 debounce 저장과 경합할 수 있었다 — 늦게 도착한 옛 스냅샷이 새 스냅샷을 덮는 순서 역전. 한 번에 하나만 날리고, 겹치면 끝난 뒤 최신 스냅샷으로 재실행하는 직렬화로 해소.

## 정리

- **알림이 거슬리면 알림을 다듬기 전에 트리거를 의심하라.** 이번 건은 UI 문제로 들어와서 동기화 시각 기록 버그로 끝났다. 패널만 예쁘게 바꿨으면 오판은 그대로 남았다.
- **성공은 상태로, 예외만 이벤트로.** 성공 알림은 처음엔 안심을 주지만 곧 소음이 된다. 상태 표시(아이콘)는 보고 싶을 때만 정보가 된다.
- **시끄러운 실패를 고칠 때 조용한 실패도 찾아라.** 백업+토스트가 뜨는 유실 경로를 고치면서, 백업조차 없이 사라지는 이웃 경로를 리뷰가 잡았다. 같은 판정 로직을 쓰는 곳은 같은 날 고치는 게 싸다.

롤백 지점: `release/pre-quiet-sync-status`. 실기기 확인 대기: 헤더 아이콘 상태 전이 감각, 다른 기기 접속 시 패널이 정말 안 뜨는지, 하드 킬 케이스에서 백업 토스트가 여전히 (정당하게) 뜨는지.
