# 여덟 번 갈아엎은 정렬 — 재배치가 아니라 제자리 스냅이었다
{: .no_toc }

**2026-07-10 — 격자 스냅부터 k-means 까지, 정리하기의 "위치 정돈"을 3일간 여덟 번 갈아엎었다. 매번 알고리즘은 검증을 통과했는데 실제 캔버스에서 깨졌다. 결론은 알고리즘 교체가 아니라 관점 전환이었다: 블럭을 "재배치"하지 말고 "제자리에서 스냅"할 것.**

## 요구사항은 처음부터 명확했다

사용자가 원한 것: *"약간 모여있는 것들 보고 걔들끼리 정렬이 깔끔하게 잘 되어야지. 덩어리 유지는 잘 되고, 군집이 뭔지 분석을 먼저 하고, 그 다음에 정렬이 들어가고, 정렬하면서 군집 간에 겹침이 있으면 군집 간에 거리 자체를 띄우는 작업이 순서대로."*

군집 분석 → 군집별 정렬 → 군집 간 분리. 파이프라인 자체는 세 번째 시도쯤에 이미 이 모양이 됐다. 문제는 각 단계를 채우는 알고리즘이 계속 실제 캔버스에서 깨졌다는 것.

## 실패의 연대기

| # | 접근 | 실패 방식 |
|---|------|----------|
| 1 | 캔버스 전체 통짜 그리드 | "너무 다 모아버려" — 사용자가 나눠둔 덩어리가 소멸 |
| 2 | 무게중심 앵커 보정 | 구석 쏠림은 잡았지만 여전히 통짜 |
| 3 | 연결요소 클러스터링 (여백 220px) | **체이닝** — A-B-C 가 조금씩 가까우면 사슬로 다 이어져 한 덩어리 |
| 4 | k-means + 실루엣 자동 K | 실제 캔버스에서 **전체 1덩어리로 뭉개짐** — k-means 는 "동그랗고 비슷한 크기"의 군집을 가정하는데 실제 덩어리는 길쭉하고 제각각 |
| 5 | 모으기(gather) 룰 제거 | 알고 보니 "다 모아버려"의 공범 — 결 중심으로 블럭을 끌어당기는 별개 룰이 격자와 충돌 |
| 6 | 평균 연결 응집 클러스터링 | 테스트 단계에서 탈락 — **긴 줄을 쪼갠다** (줄 양끝의 평균 거리가 커서) |
| 7 | 단일 연결(160px) + 군집 분리 + 안전망 | 군집·겹침은 해결. 그런데 "블럭이 너무 이동한다" |
| 8 | 밴딩(시각적 줄 정렬) | "여전히 가로지름이 있다" — 줄들을 이어붙여 고정 열 수로 다시 잘랐기 때문 |

여덟 번째까지 오고 나서야 근본 문제가 보였다.

## 진짜 문제: "재배치" 관점

1~8 전부 공통 전제가 있었다: 블럭들을 **읽기 순서로 줄 세운 다음 격자 셀에 다시 채워 넣는다**. 이 전제 아래에선 뭘 해도 어긋난다 — y 가 30px 어긋난 두 블럭의 순서가 뒤바뀌어 왼쪽 블럭이 오른쪽 셀로 날아가고(교차), 3개 줄과 2개 줄을 이어붙여 3열로 자르면 뒷줄 블럭이 앞줄로 말려 올라간다.

관점을 바꿨다. **블럭을 옮겨 담지 말고, 있던 자리에서 반듯하게만 만들자**:

```
1. 시각적 줄(밴드) = 격자 줄 그대로   ← 열 수로 다시 자르지 않는다
2. 각 블럭 = 원래 x 에서 가장 가까운 열 슬롯으로 스냅
   (같은 줄에서 슬롯이 겹칠 때만 옆으로 한 칸)
```

계단식 배치면 계단대로, 줄 길이가 달라도 그대로. 각 블럭의 이동은 "자기 자리 → 가장 가까운 슬롯"뿐이라 교차가 **구조적으로 불가능**하다. 이동량도 최소가 된다. 사용자 판정: *"이거다."*

## 안전망: 겹치면 제안하지 않는다

여덟 번의 이터레이션 중 최악의 순간들은 전부 "적용했더니 겹침"이었다. 그래서 알고리즘과 별개로 안전망을 깔았다: 파이프라인이 끝난 뒤 최종 좌표로 **모든 보이는 블럭(가이드 포함) 전수 겹침 검사**를 돌리고, 하나라도 겹치면 **정렬 제안 자체를 내지 않는다**.

"오늘은 정렬 제안이 안 뜨네"가 "적용했더니 개판"보다 백배 낫다. 겹침 사고는 이제 알고리즘이 아무리 이상해져도 사용자 캔버스에 도달할 수 없다.

## 정리

- **알고리즘의 암묵적 가정을 실제 데이터가 깬다.** k-means 는 동그란 군집을, 평균 연결은 조밀한 군집을 가정한다. 사람이 캔버스에 만드는 덩어리는 길쭉하고, 크기가 제각각이고, 경계가 흐리다. 사람의 "뭉침" 지각(게슈탈트 근접)에 가장 가까운 건 결국 제일 단순한 단일 연결이었다 — 임계값만 절제하면(220→160) 체이닝도 안 생긴다.
- **"정돈"의 반대말은 "재배치"다.** 사용자가 원한 건 자기 배치가 반듯해지는 것이지, 자기 배치가 다른 무언가로 변환되는 게 아니었다. 셀에 채워 넣는 모든 변형이 "너무 이동한다"는 피드백으로 돌아왔다.
- **품질은 알고리즘에, 보증은 안전망에.** 잘 정돈하는 것과 절대 망치지 않는 것을 한 알고리즘에 다 걸면 안 된다. 전수 겹침 검사 + 제안 폐기 한 겹이 여덟 번의 불안을 끝냈다.
- 룰 엔진이 순수 함수라 이 여정이 가능했다 — 이터레이션마다 단위 검증(마지막엔 24케이스)과 브라우저 실좌표 검증을 몇 분 만에 돌렸다.

롤백 지점은 `release/pre-tidy-snap`(및 각 이터레이션별 `release/pre-*`). 남은 튜닝 손잡이: 군집 판정 여백 160px, 셀 간격 40px, 군집 간 여백 80px.
