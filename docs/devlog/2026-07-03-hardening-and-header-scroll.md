## 무슨 일이 있었나

7월 1일 검토 때 "나중에"로 미뤄 둔 항목이 두 개 있었다 — admin 세션 하드닝, AI 라우트 실행 상한. 오늘 그걸 치우기로 했는데, 열어 보니 예상보다 심각한 게 하나 숨어 있었다. 그리고 작업 중에 태블릿 실기기 테스트 피드백이 도착했다: 터치는 전부 정상, 그런데 **헤더가 겹친다**.

## 1. env 가 비면 로그인이 뚫렸다

admin 로그인 검사가 이랬다.

```js
// 문제: env 미설정이면 undefined !== undefined → false → 통과
if (id !== process.env.ADMIN_ID || password !== process.env.ADMIN_PASSWORD) {
  return 401
}
```

`ADMIN_ID`가 설정 안 된 배포에서 body 에 `id` 를 안 보내면 `undefined !== undefined`는 false — 검사를 **통과**한다. 빈 자격증명으로 관리자가 되는 것이다. 지금 프로덕션엔 env 가 설정돼 있어 당장 뚫리진 않지만, "설정이 빠지면 잠기는 게 아니라 열리는" 방향의 실패는 방치하면 안 된다.

```js
// 해결: env 미설정 = 무조건 거부 + timing-safe 비교
if (!adminId || !adminPassword || !safeEqual(id, adminId) || !safeEqual(password, adminPassword)) {
  return 401
}
```

비교도 `===`에서 `timingSafeEqual`로 바꿨다. `===`는 앞자리부터 일치할수록 비교가 오래 걸려, 응답 시간으로 비밀번호를 문자 단위로 추측할 수 있다.

## 2. 만료가 없는 세션 쿠키

세션 쿠키 값이 `sha256(ADMIN_PASSWORD)` — **고정값**이었다. 쿠키 `maxAge`는 8시간이지만 그건 브라우저 사정이고, 서버는 언제 받아도 유효하다고 답한다. 한 번 유출되면 비밀번호를 바꾸기 전까지 영원히 산다.

```
// 해결: HMAC 서명된 만료시각 토큰 — <expiresAt>.<sig>
// 서버가 만료를 강제하고, 서명 키를 바꾸면 전 세션 무효화. 상태 저장 없음(서버리스).
1783083370902.c487df6d20d4...
```

DB 세션 테이블 없이(서버리스 유지) 해결하려고 서명 토큰을 골랐다. 로컬에서 로그인 성공/실패, 만료 검증, 위조 토큰 거부까지 curl 로 전부 확인했다.

## 3. 함수가 죽으면 환불도 죽는다 (AI 라우트)

정리하기 라우트엔 `maxDuration`이 없었다. Vercel 기본 10초 — OpenAI 가 느린 날이면 함수가 **응답 도중에** 죽는다. 문제는 그 시점이다: 크레딧은 이미 차감했고, 환불 코드는 실행될 기회가 없다. 사용자는 결과도 못 받고 한도만 깎인다.

```
// 해결: 함수 상한 60s + fetch 자체는 45s 에서 먼저 끊기 → 환불할 시간 확보
export const maxDuration = 60
fetch(..., { signal: AbortSignal.timeout(45_000) })
```

토큰 비용 방어도 같이: 응답 `max_tokens` 상한, 정리하기 프롬프트에 들어가는 블럭 수(150개)·설명 길이(300자) 상한, blocks/zones 배열 검증. 생성 라우트에도 같은 패턴을 적용했다.

## 4. "겹치면 숨기지 말고 밀리게 하자" — 헤더 가로 스크롤

실기기 피드백은 정확했다: 줄바꿈은 없는데 **겹친다**. iPad 가로에선 AI 버튼 뒤에 저장시각이 깔리고, 세로는 전부 엉킨다. 그저께 넣은 반응형(단계적 숨김)이 부족했던 것이다.

원인은 레이아웃 구조였다.

```
// 문제: 왼쪽 그룹은 min-w-0(0까지 줄어듦), 그 안의 자식들은 shrink-0(안 줄어듦)
//       → 폭이 모자라면 자식이 그룹 상자를 뚫고 나와 오른쪽 버튼 밑에 깔린다
```

flex 에서 부모가 줄어드는데 자식이 안 줄어들면, 자식은 넘친다(overflow visible). 겹침은 버그라기보다 이 조합의 당연한 결과였다.

사용자 제안이 방향을 정했다: *"모든 기기에 맞춰서 안 겹치게 만들 수가 없잖아 — 옆으로 스크롤하면 어떨까."* 맞는 말이다. 브레이크포인트별 숨김은 기기 폭 무한 경우의 수를 다 못 덮는다. 스크롤은 어떤 폭에서도 성립한다.

```
// 해결: 두 헤더 줄 모두 가로 스크롤 (스크롤바 숨김, 터치 스와이프)
overflow-x-auto [scrollbar-width:none] [&::-webkit-scrollbar]:hidden
// + 자식은 전부 shrink-0 → 줄어들지도 겹치지도 않고 옆으로 밀린다
```

저장시각은 로그인 헤더가 iPad 가로조차 넘치게 하는 주범이라 데스크톱(xl)부터만 보이게 한 단계 올렸다. 프로필 드롭다운은 Radix Portal 로 body 에 렌더되므로 스크롤 컨테이너에 잘리지 않는 것도 확인.

## 정리

- **설정이 빠졌을 때 열리는 시스템은 잠기는 시스템보다 나쁘다.** env 검사는 "없으면 거부"가 기본값이어야 한다.
- **비밀 비교는 timing-safe 로.** `===`는 응답 시간이 정보를 흘린다.
- **세션의 만료는 서버가 강제해야 한다.** 쿠키 maxAge 는 클라이언트에 대한 부탁일 뿐이다.
- **크레딧 차감과 환불 사이에서 함수가 죽을 수 있다.** 실행 상한과 fetch 타임아웃의 간격이 환불 코드의 생존 시간이다.
- **반응형에서 숨김은 경우의 수 싸움, 스크롤은 불변식.** "안 맞으면 밀린다"는 모든 폭에서 참이다.
- 실기기 피드백은 구체적일수록 강하다. "겹친다"가 아니라 **"가로에서 AI 버튼 뒤에 저장시각이 겹친다"**여서 원인 구조를 바로 찾았다.

롤백 지점은 `release/pre-hardening-header`. 배포되면 admin 세션 토큰 형식이 바뀌어 관리자는 재로그인이 필요하다. 헤더는 태블릿 세로/가로에서 재확인 예정.
