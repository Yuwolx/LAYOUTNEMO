## 방법: 렌즈 넷, 교차검증 하나

한 번의 훑기로는 못 잡는다는 걸 오전에 배웠다(높이 버그는 좌표계 렌즈로만 보인다). 그래서 각기 다른 질문을 든 감사 넷을 병렬로:

1. **성능** — 매 프레임 도는 경로에서 비싼 일을 하는 곳은?
2. **포인터 상태 머신** — 상태를 세팅해 놓고 해제 핸들러가 없는 곳은?
3. **저장/동기화** — 데이터가 유실·부활·충돌하는 시나리오는?
4. **좌표계** — transform 이 곱해진 화면 값과 world 값을 섞는 곳은?

나온 발견은 전부 코드로 재검증해 오탐을 걸러냈다. 그 결과가 확정 버그 7건 + 성능 구조 4건 + 데이터 유실 계열 10여 건.

## 배치 1 — 확정 버그 7건

백미는 **카드 높이 오염**. 카드 높이를 `getBoundingClientRect().height`로 재는데, 카드가 `scale()` 래퍼 안에 있으니 이건 배율이 곱해진 시각적 높이다. 폰(0.6배)에서는 실제의 60%가 `block.height`로 저장되고, **DB 동기화를 타고 다른 기기로 퍼진다**. 이 값을 믿는 모든 것이 무너진다 — 정리하기의 "하나라도 겹치면 제안 폐기" 안전망(폰에서 무효였다), 연결선이 카드 가장자리 대신 본문을 뚫는 것, 마퀴/갈무리 드롭의 하단 히트 결손, 새 블럭 자동 배치 겹침, 그리고 앱을 열기만 해도 높이 차이 때문에 매번 도는 불필요한 저장까지. 수정은 `offsetHeight` 한 줄 — layout 높이는 조상 transform 의 영향을 받지 않는다.

나머지: 블럭 우클릭이 포인터를 영구 점유해 캔버스를 잠그는 것(맥 계열은 contextmenu 가 mousedown 시점에 떠서 pointerup 이 안 온다), 드래그 중 스페이스 탭이 좀비 드래그를 만드는 것, 게스트 초기화가 pagehide flush 에 되살아나는 것(아침에 넣은 debounce 의 부작용 — 새 코드는 새 구멍을 판다), 핀치 중 두 번째 손가락이 상세를 여는 것, 끊긴 마퀴가 유령 선택을 확정하는 것, 저장 예외 시 재시도 플래그 소실. 우클릭 잠금과 스페이스 좀비는 테스트로도 박았다(이제 6개).

## 배치 2 — 리렌더 격리

localStorage 디바운스로 저장 비용은 없앴지만 구조는 그대로였다: 드래그·팬 중 **매 프레임 페이지 전체가 리렌더**되고, 캔버스 위 모든 카드가 통째로 다시 그려진다. 카드 수에 비례해 나빠지는 구조.

- **카드 메모 경계**: 카드를 `React.memo` 래퍼로 감싸고, 콜백은 identity 가 안정된 handlers 객체 하나로. 이제 팬/핀치 중 카드 리렌더 0장, 드래그 중엔 드래그되는 카드만.
- **뷰포트 보고 디바운스**: 새 블럭 위치 제안용 뷰포트 보고가 매 프레임 부모 setState 를 해서, pan 을 캔버스 로컬 state 로 격리한 설계를 스스로 우회하고 있었다. 150ms 모아서 보고.
- **리스너 재구독 제거**: 드래그 리스너 effect 의 deps 에 매 프레임 바뀌는 값들(blocks·pan·offset)이 있어 pointermove 마다 window 리스너 3개를 떼었다 붙였다. 최신값은 ref 로 읽고 deps 는 on/off 스위치만.
- 관계선 SVG `useMemo` — 팬/핀치 프레임에서 전량 재생성 제거.

## 배치 3 — 데이터가 사라지고 되살아나는 길목들

가장 굵은 것: **삭제한 블럭이 부활한다**. 삭제는 DB 행을 지우는데(hard delete) 저장은 캔버스 전체 스냅샷 upsert 라, 삭제 사실을 모르는 다른 탭/기기가 편집 한 번만 해도 지운 행이 되살아난다. 웃긴 건 캔버스에는 이미 tombstone 설계가 있었고(6월에 같은 이유로 도입), `is_deleted` 컬럼과 타입까지 있는데 **true 로 쓰는 코드만 없었다** — 배관을 절반 깔다 만 것. 삭제를 `isDeleted` 마킹으로 전환하니 부활 통로가 구조적으로 닫히고, redo desync 와 삭제 API 실패 유실까지 같이 해소됐다(마킹은 일반 저장 경로에 편승하므로). 30일 지난 tombstone 은 로그인 때 하드 정리.

그 외: 클라우드 저장 성공 시마다 동기화 시각 기록(전엔 로그아웃에만 기록해서, 탭을 그냥 닫은 세션의 편집이 다음 로그인 때 백업 없이 사라질 수 있었다), 로그인 병합 후 히스토리 리셋(Undo 한 번에 동기화 이전으로 롤백되던 것), 빠른 계정 전환 레이스 가드, tombstone 된 캔버스 id 재사용 차단, 손상된 localStorage 대피 후 진행, 타 계정 캐시 백업.

## 정리

- **같은 코드도 렌즈를 바꾸면 다른 버그가 보인다.** 성능 렌즈는 높이 오염을 못 보고, 좌표계 렌즈는 부활 버그를 못 본다. 감사는 질문별로 나눠서.
- **반쪽 배관이 제일 위험하다.** `is_deleted` 컬럼이 "있다"는 사실이 "쓰인다"는 착각을 만든다. 도입할 거면 끝까지, 안 쓸 거면 지워라.
- **화면 좌표와 world 좌표는 타입이 다르다고 생각하라.** `getBoundingClientRect` 는 transform 이 곱해진 값 — world 단위 저장소에 넣는 순간 오염이 동기화를 타고 퍼진다.
- **고친 손이 새 구멍을 판다.** 아침의 debounce 가 저녁의 초기화 버그였다. 수정에는 반드시 "이 변경이 무효화하는 가정이 뭐지?"를 물을 것.

세 배치 각각 롤백 지점: `release/pre-audit-batch-1`, `release/pre-render-isolation`, `release/pre-sync-durability`. 남은 항목(결 hard delete, 멀티탭 병합, pagehide 클라우드 flush)은 로드맵에.
