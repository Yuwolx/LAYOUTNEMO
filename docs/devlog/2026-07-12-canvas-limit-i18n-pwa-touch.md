## 무료 캔버스는 1개 — 유료화 첫 발

Polar 웹훅(plan pro/free 전환)이 들어온 데 이어, 이번엔 클라이언트 쪽 한도를 걸었다. 무료 계정은 캔버스 1개, pro와 마스터 계정은 무제한.

한도의 단일 소스는 `lib/constants/plans.ts` 하나로 시작했다. AI 월 한도는 서버(`lib/ai/quota.ts`)가 강제하고, 캔버스 개수는 클라이언트가 강제한다 — 캔버스 생성 경로가 `handleCreateCanvas` 하나뿐이고 백업은 내보내기만 있어서(가져오기 없음) 우회로가 없다는 걸 확인하고 내린 결정이다. 삭제된 캔버스(tombstone)는 로드 시점에 걸러지므로 한도 계산에 유령이 끼지도 않는다.

문구도 같이 손봤다. 비로그인 안내가 "로그인하면 여러 캔버스를 사용할 수 있어요"였는데, 이제 로그인해도 무료면 1개라 거짓말이 된다 — "로그인하면 캔버스가 기기 간에 동기화돼요"로 교체. 기능을 잠글 때는 그 기능을 약속하던 문구부터 찾아야 한다.

## 제목은 영어인데 본문은 한국어

영어 모드에서 최초 접속하면 가이드 블럭 제목은 "User Guide"인데 본문이 한국어로 나온다는 제보. 시드 번역 데이터(`seed.ts`)에는 영어 본문이 멀쩡히 다 있었다.

이 앱의 시드 번역은 "저장된 값이 한국어 원문과 **정확히 일치할 때만** 번역을 겹쳐 보여주는" 전략이다. 사용자가 편집한 블럭을 번역으로 덮지 않기 위한 설계인데, 뒤집으면 **원문이 한 글자라도 어긋나면 번역이 조용히 풀린다**는 뜻이다. 실제로 page.tsx의 원본과 seed.ts의 사본을 프로그램으로 diff까지 해봤는데 완전 일치 — 그럼 뭐가 어긋났나.

저장된 데이터였다. 가이드 본문은 그동안 여러 번 개정됐다(8초 자동 반영, 대표 블럭 섹션 추가…). 옛 버전을 쓰던 계정의 DB에는 옛 한국어 본문이 남아 있고, 이걸 최신 원문으로 갱신해주는 `migrateGuideBlock`이 **localStorage 로드 경로에만 걸려 있고 Supabase 로드 경로에는 빠져 있었다**. 제목 "사용 설명서"는 한 번도 개정된 적이 없어서 일치 → 영어. 본문은 개정됨 → "사용자 편집"으로 오판 → 한국어. 제목만 영어인 기묘한 증상이 그대로 설명된다.

덤으로 하나 더: 새 캔버스를 만들 때 복제되는 가이드 블럭은 id가 UUID로 바뀌는데, 시드 번역은 id로 찾기 때문에 매핑이 아예 끊긴다. 가이드는 편집 불가 + 제목 불변이므로 제목("사용 설명서"/"단축키")으로 폴백 매칭하게 했다.

문제 → 해결 두 줄:

```
문제: 원격 로드가 migrateCanvas 를 안 거침 → 옛 본문이 '편집됨'으로 오판되어 번역 해제
해결: setCanvases(orderedRemote.map(migrateCanvas)) + 가이드는 제목 폴백 매칭
```

## 코드에 없던 터치 버그

폰에서 세로는 멀쩡한데 가로로 돌리면 터치가 어긋난다는 제보. 캔버스 좌표 코드를 다 뒤졌다 — 전부 이벤트 시점에 `getBoundingClientRect`로 위치를 새로 재는 구조라, 회전한다고 깨질 캐시가 없다. 막다른 골목.

그래서 코드를 더 파는 대신 세 가지를 물었다. 브라우저인지 PWA인지, 가로인지 180° 뒤집기인지, 어긋남이 전체 균일인지 특정 영역인지. 답: **PWA + 가로 + 화면 전체가 균일하게, 인식 영역이 실제 터치보다 위**.

이 세 조각이 맞으면 답은 하나다. iOS 홈 화면 앱(standalone)은 세로에서 상태 바 아래에 웹뷰를 배치하는데, 가로로 회전하면 상태 바가 사라지면서 렌더링 위치와 터치 좌표계가 상태 바 높이만큼 어긋나는 **iOS의 오래된 버그**다. 태블릿은 상태 바 처리 방식이 달라 안 겪는 것까지 일치. 앱 코드에는 원인이 없으니 아무리 뒤져도 안 나왔던 거다.

처방은 표준대로 `viewport-fit=cover` — 웹뷰가 처음부터 화면 전체를 덮으면 회전해도 어긋날 자리가 없다. 대신 콘텐츠가 노치·홈 인디케이터 영역까지 확장되므로 safe-area 패딩을 같이 깔았다: 헤더 좌우(가로에서 노치 밑에 버튼 안 깔리게), 갈무리함 독·좌하단 컨트롤·연결 안내는 `max(기존 여백, env(safe-area-inset-*))`. 노치 없는 기기에서는 기존과 동일하다. 터치는 로컬 검증이 불가능하므로 실기기 가로 모드 확인이 남아 있다.

## 정리

- **진단 질문 세 개가 코드 리딩 몇 시간보다 쌌다.** "어디서(PWA?), 어떤 자세로(가로?), 어떻게(균일? 부분?)"가 갖춰지니 원인이 코드 밖(iOS 웹뷰)이라는 게 바로 드러났다. 재현 환경 정보 없이 blind fix 하지 않기.
- **"원문 일치" 번역 전략은 원문 개정에 취약하다.** 원문을 고칠 때마다 저장된 옛 사본과 어긋난다 — 로드되는 **모든** 경로에서 시드 콘텐츠를 최신화해야 성립하는 전략이다. 경로 하나(원격)가 빠져 있었다.
- **기능을 잠글 때는 그 기능을 약속하던 문구부터.** "여러 캔버스를 쓸 수 있어요"는 한도 도입과 동시에 거짓말이 된다.

롤백 지점은 `release/pre-canvas-limit`.
