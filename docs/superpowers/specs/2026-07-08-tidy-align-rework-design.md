# 정리하기 "정렬" 대대적 개편 — 설계 문서

- 날짜: 2026-07-08
- 대상 파일: `lib/tidy/rules.ts` (룰 #4 "줄/열 맞춤")
- 배경 메모: 에이전트 메모리 `next-session-plan.md`, `touch-support-pr.md`

## 문제 정의

정리하기의 "정렬" 제안을 두 번 구현했고 둘 다 사용자 판정 "정렬 안 됨":

- **v1** (격자 24px 스냅): 최대 12px 이동 → 눈에 안 보임.
- **v2** (`480de3a`, 현재 코드): y/x가 48px(`ALIGN_TOLERANCE`) 이내로 뭉친 블럭을 클러스터로 묶어 공통 라인에 스냅. 목표값을 다시 24px 격자에 스냅.

**진단(사용자 확인 완료)**: v2 제안은 **떴으나 적용해도 티가 안 났다.** 원인:

1. 이미 라인에 가까운(≤48px) 블럭만 잡아 그 라인으로 스냅 → 원래 20px 근처였던 블럭은 20px만 이동.
2. 목표를 24px 격자에 재-스냅 → 이동량을 더 깎음.
3. 결과적으로 "가까운 건 거의 안 움직이고, 먼 건 아예 클러스터에 안 잡힘."

사용자 요구: **"적용하면 한눈에 정돈된 게 보여야 한다."**

## 방향 (사용자와 합의)

- 범위: **캔버스 전체** (결 구분 없이). 결별 그리드 패킹(전면 재배치)은 거부.
- 강도: **중간** — "대충 줄은 끌어오되 대략적 위치·구조는 유지." 전면 재배치는 거부.
- 접근: **줄 우선(rows-first)** 정돈.

## 알고리즘: rows-first 정돈

입력: 정렬 대상 블럭 `alignable` = 룰 대상 블럭 중 모으기(#3) 대상 제외분(현행 유지). 각 블럭은 `{x, y, width, height}`.

### 1단계 — 가로 줄 클러스터링 (y축)

- 블럭을 y(상단 좌표) 기준 정렬.
- **gap 기반 클러스터**: 정렬된 순서에서 인접 블럭의 y 차이가 `ROW_TOLERANCE`를 넘으면 그 지점에서 줄을 끊는다. (running-mean 방식 대신 gap 기반 — 순서 의존성이 적고 이해하기 쉬움)
- 2개 이상인 클러스터만 "줄"로 채택.

### 2단계 — 각 줄 정돈

줄에 속한 블럭들에 대해:

1. **공통 y로 맞춤**: 줄의 y 평균값으로 모든 블럭의 y를 설정. (격자 재-스냅 안 함 — v2의 이동량 깎기 제거)
2. **가로 간격 균등화 (양끝 고정 분배)**: 블럭을 x로 정렬 → 가장 왼쪽 블럭의 좌변과 가장 오른쪽 블럭의 우변은 **고정**, 사이 블럭들을 인접 블럭 간 **edge gap이 균일**해지도록 재배치.
   - 균일 gap = `(범위 총폭 − 블럭 폭 합) / (블럭 수 − 1)`.
   - gap이 `GATHER_GAP`(24px) 미만이면(범위 안에 다 안 들어가면) gap을 `GATHER_GAP`으로 고정하고 오른쪽 끝을 필요한 만큼 확장. (겹침 방지)

### 3단계 — 나머지 블럭 세로 열 정돈 (x축)

- 어느 줄(2단계)에도 **속하지 않은** 블럭만 대상 (줄/열 배타 배정 → x/y 지정 충돌 방지).
- x(좌변) 기준 gap 클러스터, `COL_TOLERANCE` 사용.
- 2개 이상 열: ① 공통 x(평균)로 맞춤 ② y 간격 양끝 고정 균등화 (2단계의 축 전치).

### 4단계 — 제안 생성

- 위 이동 중 실제 이동량이 `ALIGN_EPSILON`(1px) 초과인 것만 change로 수집.
- 의미 있게 움직이는 블럭이 `MIN_ALIGN_BLOCKS`(2) 이상일 때만 단일 "정렬" 제안 발행.
- 현행처럼 `type: "position"`, 단일 suggestion(`rule-align`), 체크리스트 일괄 적용 → 히스토리 1커밋.
- 적용 필드는 x/y만 (기존 화이트리스트 내).

## 파라미터 (초기값, 라이브 튜닝 대상)

| 상수 | 초기값 | 근거 |
|---|---|---|
| `ROW_TOLERANCE` | 72px | 블럭 높이(116~168) 약 0.5배. 줄 지터는 묶고 다른 줄은 안 묶음. |
| `COL_TOLERANCE` | 120px | 블럭 폭(280) 약 0.43배. |
| `MIN_GAP` | 24px (= `GATHER_GAP`) | 균등화 시 최소 간격, 겹침 방지. |
| `ALIGN_EPSILON` | 1px | 무의미 이동 제외 (현행 유지). |
| `MIN_ALIGN_BLOCKS` | 2 | 제안 발행 최소 이동 블럭 수 (현행 유지). |

제거: **정렬(#4)에서** `ALIGN_GRID`(24px) 격자 재-스냅 사용 — 이동량을 깎던 v1/v2의 근본 원인. `ALIGN_GRID` 상수와 `snapToGrid` 함수 자체는 모으기(#3)가 계속 쓰므로 남긴다. 정렬에서만 호출을 걷어낸다.

## 왜 이번엔 티가 나는가

- **넓은 허용범위(72/120px)**: v2의 48px보다 커서 더 흩어진 블럭도 줄/열에 편입 → 스냅 이동이 큼.
- **간격 균등화**: 라인 위에 이미 있던 블럭도 좌우(또는 상하)로 재분배됨 → 이동량이 작았던 클러스터도 눈에 보이게 정돈. **이것이 v1/v2에 없던 핵심 차이.**
- **격자 재-스냅 제거**: 목표가 클러스터 실제 평균 → 이동량이 안 깎임.

## 범위 밖 (이번 사이클 제외)

- **적용 전 미리보기(고스트 위치)**: 신뢰도 향상용. 별도 UI 작업 → 다음 후보.
- **드래그 중 스냅 가이드(피그마식 빨간 선)**: 별개 기능.
- **모으기(#3) 개편**: 이번은 "정렬"만. 모으기는 현행 유지, 정렬은 모으기 대상 제외(현행 로직 유지). 모으기의 `snapToGrid`는 이번 변경과 무관하므로 그대로 둔다.
- **결별 오토 레이아웃(A안)**: 사용자 거부.

## 엣지 케이스

- **줄 안 블럭 폭 합 > 범위**: 균등화가 겹침 유발 → gap을 `MIN_GAP`로 고정하고 우측 확장.
- **한 줄에 블럭 1개**: 줄로 안 잡힘 → 3단계 열 후보로 넘어감.
- **줄에도 열에도 안 드는 고립 블럭**: 이동 없음 (정상).
- **완벽 정렬 캔버스**: 이동 블럭 0 → 제안 안 뜸 (정상).
- **모든 블럭이 촘촘한 사다리(y 간격 ≈ ROW_TOLERANCE)**: gap 클러스터가 한 줄로 과다 병합될 수 있음. 실사용 freeform 캔버스에선 드물다고 판단. 라이브에서 과병합 관찰 시 `ROW_TOLERANCE` 하향.

## 테스트 전략

`lib/tidy/rules.ts`는 순수 함수(`generateRuleSuggestions`) → 단위 테스트 가능.

- 흩어진 3블럭 줄 → 공통 y + 균등 x, 실제 이동량 검증.
- 균등화가 양끝 고정하는지 (leftmost 좌변·rightmost 우변 불변).
- 폭 합 초과 시 MIN_GAP 확장·비겹침.
- 줄/열 배타 배정 (한 블럭이 x·y 동시에 두 소스에서 안 받는지).
- 모으기 대상 블럭 제외 유지.
- 이동 블럭 < 2면 제안 미발행.

로컬 검증: `npx tsc --noEmit` → `npm run lint` → `npm run build`. 실제 정렬 감각은 배포 후 실기기(사용자 캔버스)에서만 확인 가능.
